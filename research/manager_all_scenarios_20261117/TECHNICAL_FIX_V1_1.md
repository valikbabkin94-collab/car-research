# Техническая поправка до интерпретации результатов

Первый запуск44087096459 использует исходный run.py. Обнаружена ошибка Python groupby: сортировка ленивых групп после их создания исчерпывает итераторы, поэтому обработка сигналов может получить пустые группы. Это не результат ШУМ и не исследовательский вывод. Старые файлы run.py и их SHA сохранены без изменений; новый execute_v1_1.py исправляет только обход групп и добавляет обязательное равенство числа feature-записей числу входов. Гипотезы, сетка, входы, периоды и статистические пороги не менялись. После завершения первого запуска сохраняется его численный кэш; исправленный запуск использует его, не скачивает готовые окна повторно. Любые пустые результаты первого запуска недействительны. Итоговые выводы только по версии1.1 и после проверки покрытия.

До первого корректного расчёта исправлено также соответствие X1 текущему исходнику: manager ATR берётся из закрытых часов на момент исходной публикации, а не позднего limit-fill. Геометрия переносится к неизменённому fill. В X4/X5 ATR остаётся на входе. В случайном контроле сохраняется исходная задержка signal->entry, поэтому signal timestamp сдвигается вместе с entry. Это исправление соответствия формуле действующего исходника, не подбор нового параметра. Первый запуск использовал пустые группы и не дал годных торговых результатов. Исправленный запуск наследует его ASOF; новая будущая история не добавляется.

Конфлюэнс дополнительно требует, чтобы второй вход уже произошёл к первому: в архиве только исполненные сигналы, поэтому выбор подтверждения из будущего filled-журнала создавал бы скрытый look-ahead. Это консервативная верхняя граница времени получения сигнала при отсутствии receipt; ±2ч остаётся диагностикой, primary только ранее доступное подтверждение. Порог2ч/4ч и состав сетки неизменны.
