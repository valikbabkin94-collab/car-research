# Обязательная сверка с исходным P1–P3 до итогового вывода

Сверка кода с pinned channels_audit_v2/engine.py выявила два отличия адаптера:

1. Исходный P1/P2/P3 проверяет ВСЕ авторские TP относительно цены нового входа до выбора одного/двух TP. Поэтому P1 не должен входить после пройденного TP1 даже если последняя цель впереди.
2. Исходный структурный P2 и команда MOVE_BE структурного P1 ставят стоп ровно на вход, без fee-buffer0.11%. Fee-buffer сохраняется у T1–T3/O0, как в их исходной модели.

Это исправление соответствия ранее указанному исходному алгоритму, не выбор новых параметров по PnL. Финансовые H1/H2 агрегаты при решении об исправлении не просматривались. Весь исходный run44270512713/его строки сохраняются. Авторитетный итог — verified_final, а не промежуточный final.

Повторно рассчитываются ТОЛЬКО структурные P1/P2/AUTHOR случаи, где прежний путь фактически завершился BE и изменение его цены может изменить дальнейший путь. Если BE не сработал, путь при менее тесном нулевом стопе не меняется, результат переиспользуется. Проверка пройденной первой цели выполняется по сохранённой цене входа, без пересчёта пути. Все исходы Олега и прочие политики переиспользуются без изменений. Для исходных приватных чатов/текстов новых обращений нет.

Результаты исправления, старый/новый статус и PnL — CONFORMANCE_LOG.json; это не скрытая замена неудачных запусков. Полные версии/commit SHA и признаки повторного использования остаются в checkpoint.
