## Что проверить, используя готовые расчёты

1. Протокол443a288cea746f8756dfb93fe781e0d338ceb30f, parser/policies/tests commits до запуска и последующие явные implementation fixes. Код заморожен до просмотра PnL; исправления не подбирались по итогам. Все версии сохранены, SOURCE_CONFORMANCE_RU описывает восстановление исходного P1–P3, а RECOVERY_AUDIT — строковые funding rates.
2. Последняя snapshot-редакция используется после max(pub,edit_date), не в исходном прошлом. Reply-chain root должен быть причинно доступен; альтернативная связь только по одной монете/стороне/7д. Отсутствуют полная история редакций и identity авторов в анонимизированных каналах — не приписывать поток одному человеку.
3. Слово «Targets» в Entry Targets/Stop Targets не должно превращать цену входа/стопа в TP. Кириллическое «ТР» и процентный SL учитываются отдельно. Вход «по рынку» не равен цене последующего «Усреднение». DCA/неопределённая частичная фиксация не придуманы; AUTHOR соответствующих случаев UNRESOLVED.
4. OLEG не равен OLEG_MAIN. Опубликованный source OLEG использует author levels и BE; OLEG_MAIN4% — отдельный feed, не источник13 сделок. O0 является code-baseline proxy, не доказанной runtime-репликой; неизвестные reversal/config/полные fills не восстанавливались по прибыли13 сделок. initial_stop из live — аварийный, не финансовый1R.
5. P1 — full finalTP+авторские команды, но вход запрещён если хотя бы первая авторская цель уже позади; P2 — первые2TP50/50 и BE точно наentry; P3 — full TP1. OLEG/T модели BE используют свой объявленный fee-buffer. SOURCE_CONFORMANCE_LOG содержит только потенциально изменённые BE-пути; все исходы Олега и остальные пути сохранены. Не запускать заново все матрицы.
6. final_rows/FINANCIAL_IDENTITY подтверждает, что финальная правка только классифицировала несовместимую сторону/когорту до проверки котировок. Уже исполненный PnL не менялся. Длинные сигналы O1 не должны считаться его price gap; текстовые сигналы не должны увеличивать price gap P1–P3.
7. Taker0.055% на каждое изменение,5bps market/SL/time slip; funding по остатку baseqty и1mclose proxy. Проверить rate/ts string normalization, boundary payments, отсутствие подмены неизвестного нулями без stress. netR_adverse удваивает комиссии/slip и добавляет funding±.01%/8h для неизвестности.
8. Source midpoint/last40 из всех исходных дат зафиксированы до PnL. H1 не использует закрытия после границы; NOFILL сTTL после H1 границы не известен на H1. Лучший выбирается только по H1, n>=60/cov>=95%; raw максимум не равен допущенному. Last40 перекрывает H2. Открытые P1 позиции не закрывались искусственно, censored H2/last40 блокирует продвижение.
9. Парный контроль — фиксированная случайная дата той же монеты/направления в том же временном срезе±7д, один контроль на сигнал, без перерисовки gaps. Авторские абсолютные расстояния масштабируются относительно новой цены. Будущие реальные авторские команды в random baseline не переносятся; поэтому AUTHOR excess смешивает timing и management, не является чистой проверкой timing. BH по140 слотам, H2 иlast40 отдельно; отсутствующие/малые слоты p=1.
10. MATCHED_OLEG_POLICY_COMPARISON сравнивает одни и те же входы/возможности для O0/O3/O4/O5/AUTHOR, включая NOFILL0. TWO_AUTHOR_TP_ONLY — фиксированная структурная подгруппа для проверки BE без смешивания числа целей; не выбирать по ней новую стратегию. Риск-подписи только описательные, никаких найденных порогов.
11. Profit% сверяется только с завершёнными1m свечами ДО времени заявления. Market-entry envelope не доказывает авторский реализованный ROI: иные вход/плечо/доли/капитал могут быть неизвестны. Exceeds unlevered envelope не означает «автор врёт». Unlinked reports не превращать в сделки.
